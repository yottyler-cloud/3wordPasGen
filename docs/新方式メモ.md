## 現行方式のしくみ（最新版）
- 入力: キーワード3つ（前後の空白は除去、全角→半角のNFKC正規化）
- 3つを区切りなしで連結 → SHA-512(16進) → `random.seed()` → MT19937
- 大文字・小文字・数字を必ず2文字ずつ、記号ありは記号も2文字、残りは全種からランダム、最後にシャッフル
- 除外文字: `l` `1` `O` `0`
- 文字数: ブラウザ版は 8/12/16/20（初期12）。Python版は12固定
- 色分け表示: 数字=青、小文字=赤、その他=黒

## 検証で分かったこと（新方式を作る動機）
- 出力パスワード自体は強い（12桁・記号込みの直接総当たりは事実上不可能）
- 弱点は「入口」= キーワードの組み合わせ。パスワードが1つ漏れると、総当たりでキーワードを逆算されうる
  - 実測: この環境のPython・1コアで毎秒約5万回。「あああ/いいい/ううう」は約2.5秒・12万回で判明
  - GPUや専用機なら桁違いに速い。ベタな単語3つだと数分〜数日で破られうる
- 原因: 1回の計算が軽い（SHA-512一発）＝ 総当たりする側に有利

## 新方式の設計方針（ユーザーの希望）
材料を増やして入口を狭くする。優先度は「覚えやすさを保つ」。
1. **暗証番号的な秘密**（全サイト共通の「秘密の芯」。ユーザーが設定）← 新規追加
   - 4桁でも効果あり（×1万）、できれば6桁や数字以外も混ぜられると安心
   - 銀行の暗証番号同様、人は忘れにくい想定
2. キーワード × 3（現行どおり）
3. **サイト名**（任意。入れればサイト別に別パスワード。使い回し問題を解消）
   - サイト名は秘密ではない。書き方をそろえる仕組みが必要（小文字統一など）

### 保留にした対策（必要なら後で）
- 計算を重くする（PBKDF2 / Argon2）… 総当たりを大幅に遅くできるが、今回は一旦保留
- 弱いキーワードの警告（くり返し・連番・空欄・短すぎを赤で知らせる）
- キーワード欄を可変（5〜6個でベタな単語でも安全圏）

### 注意点
- 新方式は現行と結果が変わる → 必ず別ページ/別ファイルで作る
- 暗証番号を忘れると全パスワードが作れない（本人向けヒントの工夫）
- サイト名の表記ゆれ対策（例: 小文字化・ドメイン主要部のみ）
- オフライン・通信禁止・「保存しない」という現行の長所は維持する

### 作るときに最初に決めること
- 暗証番号は必須か任意か / 桁数・文字種
- サイト名は必須か任意か / 表記そろえのルール
- 文字数の初期値・選択肢
- 現行方式との切り替えUIを同じページに置くか、別ページにするか
